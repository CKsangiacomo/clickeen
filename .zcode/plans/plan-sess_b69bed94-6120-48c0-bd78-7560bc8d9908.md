## 128C + 128D Implementation Plan — Product Copilot Native Tool Agent + Bob/Roma Transport

### Scope

This is the largest slice in PRD 128. It rebuilds the Product Copilot brain from a six-kind JSON protocol to a streaming text + native tool agent, and rewires the Bob↔Roma↔Product Copilot transport from non-streaming JSON to SSE with tool-call/observation loops.

### What gets deleted

**Product Copilot Worker (`agents/product-copilot/src/`):**
- `index.ts` — delete: six-kind response types, JSON parser, prompt builder for JSON envelope, structural retry, `validateModelResponse`, all six-kind validation. Keep: `ProductCopilotInputError`, conversation history limits, context prompt building (adapted).
- `worker.ts` — delete: `/model/chat` call, six-kind response packaging. Replace with `/model/turn` streaming call.
- `evals/product-copilot.json` — delete (tests the obsolete envelope)
- `evals/run-product-copilot-eval.ts` — delete (tests the obsolete envelope)
- `evals/real-eval.ts` — delete (direct OpenAI calls, six-kind scoring)

### What gets created/rewritten

**1. Product Copilot brain (`agents/product-copilot/src/index.ts`):**
- New `executeCopilotTurn` function that:
  - Builds Builder instructions (system prompt adapted from current — no JSON envelope instruction)
  - Builds context from the same control catalog + current values
  - Defines `apply_widget_ops` tool using `inputSchema` (not `parameters`)
  - Calls San Francisco `POST /model/turn` stream mode via service binding
  - Returns a ReadableStream of Product Copilot events (agent_turn_started, text_delta, tool_call, model_step_finished)
  - Accepts continuation calls when Bob sends a tool result
  - Emits agent_turn_finished or agent_turn_error
- Keeps: conversation history bounds (8 messages, 2000 chars), context size limit (120K chars), control validation (WidgetOp validation against control catalog stays in Bob, not here)

**2. Product Copilot Worker (`agents/product-copilot/src/worker.ts`):**
- New `POST /turn` endpoint (replaces `POST /execute`):
  - Accepts `{ version: 1, kind: "initial" | "continuation", sessionId, userTurnId, grant, selectedModel?, conversationHistory, currentDraftContext, ... }`
  - Calls the brain, which calls San Francisco `/model/turn`
  - Returns `text/event-stream` with the seven event types
  - Handles cancellation via AbortSignal

**3. Roma route (`roma/app/api/account/instances/[instanceId]/copilot/route.ts`):**
- Rewrite `POST` handler:
  - Accept versioned union (initial/continuation)
  - Initial: validate, mint grant, reserve turn, call Product Copilot `/turn`, stream SSE through to Bob
  - Continuation: reauthorize, forward to Product Copilot `/turn`, stream SSE
  - Both: transparent SSE relay (no reinterpretation of events)

**4. Roma copilot library (`roma/lib/ai/account-copilot.ts`):**
- Update `executeCopilotOnProductCopilot` to:
  - Call `/turn` instead of `/execute`
  - Stream the SSE response instead of buffering JSON
  - Return a ReadableStream (SSE passthrough) instead of `{ ok, requestId, result }`

**5. Bob transport (`bob/lib/session/sessionTransport.ts`):**
- Update copilot path to support SSE streaming:
  - The `run-copilot` command dispatches to Roma
  - Roma streams SSE events back through postMessage (incremental `host:agent-event` messages)
  - Bob's transport reads events as they arrive (not one buffered response)

**6. Bob host handler (`roma/components/builder-domain.tsx`):**
- Update `runBobAccountCommand` to handle SSE from the copilot route:
  - For `run-copilot`: fetch the route, get the SSE stream, forward each event to Bob via postMessage
  - For `cancel-copilot`: abort the active request's AbortController

**7. Bob Copilot UI (`bob/components/CopilotPane.tsx`):**
- Rewrite event handling:
  - `agent_turn_started` → set loading state
  - `text_delta` → append to streaming message text
  - `tool_call` → validate WidgetOps against controls → apply via `session.applyOps` → build undo → send continuation
  - `model_step_finished` → record usage
  - `agent_turn_finished` → mark complete
  - `agent_turn_error` → show error
  - `agent_turn_stopped` → show stopped
- Send/Stop toggle: Send starts initial request, Stop sends `cancel-copilot`

**8. New tests:**
- Product Copilot brain tests (tool call construction, context building, continuation)
- Product Copilot Worker tests (initial/continuation dispatch, SSE event format)
- Bob tool execution tests (apply WidgetOps from tool_call, send continuation with result)

### Key design decisions

- **Tool definition**: `apply_widget_ops` uses a JSON Schema derived from the existing `ProductCopilotWidgetOp` union. The schema is shared in ck-contracts so both Product Copilot and Bob reference the same truth.
- **SSE relay**: Roma does NOT buffer the Product Copilot stream. It pipes the SSE response body directly through to Bob. Roma only adds authorization and grant minting.
- **Bob tool execution**: when Bob receives a `tool_call` event, it validates the WidgetOps against the current compiled controls, applies them through `session.applyOps` (existing engine), builds undo, then sends a `continuation` request with the tool result. This is synchronous from Bob's perspective — the user sees "working..." while Bob executes and sends the continuation.
- **No new storage**: conversation history lives in Bob's browser memory. Turn correlation uses Bob-issued `userTurnId`. No server-side conversation store.
- **Cancel**: `cancel-copilot` host command → Roma aborts the active fetch → Product Copilot Worker sees the abort → stream ends with `agent_turn_stopped`.
