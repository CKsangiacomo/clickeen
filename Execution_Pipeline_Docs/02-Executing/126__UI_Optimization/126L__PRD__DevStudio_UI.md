## 2026-07-30 DevStudio Convergence Correction

The original L1/L2/L3 evidence remains valid for the shell and small-contract
scope it executed. It is not evidence that DevStudio reveals or consumes a
complete Dieter design system. The current hardcoded `.docs-shell*`,
`.devstudio-page*`, custom Core styles rows, and app-local popup presentation
are correction inputs.

DevStudio must become both:

1. the real consumer of Dieter's Layout, Table, and Popup contracts; and
2. the faithful source-derived documentation surface for those contracts.

### Exact Shell Migration

The actual application shell becomes:

```html
<div class="main-container" data-navigation-open="true|absent">
  <aside class="left-nav">existing DevStudio navigation</aside>
  <main class="page">current route content</main>
</div>
```

The markup/classes and CSS come from
`dieter/layouts/main-container/{html,css,spec.json}`. DevStudio owns the
navigation items, route state, page content, and navigation-open state; it does
not own a parallel shell appearance.

The initial Dieter visual values are `13.75rem | minmax(0, 1fr)` in Full,
`100dvh`, nav-owned scrolling/padding, and page-owned scrolling with
`var(--space-8)` safe-area padding. Compact geometry, scrim visual, and the
`600px` classifier come from the same source. DevStudio owns the trigger/scrim
click state and unsupported portrait message, not their base layout appearance.

Every DevStudio route uses the shared Page foundation:

```text
page
├── page__header
│   ├── title/description
│   └── page__actions
└── page__content
```

Delete replaced `.docs-shell*`, `.devstudio-page-layout`, and redundant
`.devstudio-page*` layout rules in the same migration. Keep only
DevStudio-specific route content that does not duplicate Dieter.

The exact class migration is:

- delete `.docs-shell`, `.docs-shell__sidebar`, `.docs-shell__main`,
  `.docs-shell__compact-bar`, `.docs-shell__menu-toggle`, and
  `.docs-shell__scrim` plus their media declarations;
- retain nav-content styling by remapping `.docs-shell__brand`,
  `.docs-shell__brand-title`, and `.docs-shell__nav` to
  `.devstudio-nav__brand`, `.devstudio-nav__title`, and
  `.devstudio-nav__content`;
- delete `.devstudio-page-layout` and its direct-child rules;
- delete `.devstudio-page` border/radius/background/padding and the generic
  `.devstudio-page-section` margin/background/padding/radius;
- remap `.devstudio-page__header` to `.page__header`;
- put route actions in `.page__actions` and route bodies in `.page__content`;
- keep route-specific Entitlements/LLM/token-state classes without generic
  page/section chrome.

### Foundations And Component Presentation

Foundations becomes:

```text
Core styles
Colors
Icons
Typography
Layouts
```

The new `#/dieter/layouts` route is generated by the existing foundation
generator from the real Dieter Layout source. It contains a short explanation,
source markup, and actual Full, Compact-closed, and Compact-open renderings.
Each rendering runs inside an isolated iframe sized to the applicable real
viewport so production media queries execute honestly. The iframe document
uses the exact Dieter HTML/CSS source. DevStudio owns only iframe dimensions,
clipping, labels, and example nav/page content; copied inner layout CSS or
preview-mode overrides are forbidden.

Below the examples, render the exact `editableTokens` inventory from
`main-container.spec.json`. Edit opens the existing token editor for the
selected Dieter token. The existing authenticated token read/commit path,
confirmation, dirty-state behavior, and GitHub source authority remain
unchanged. Do not create layout persistence, a CSS editor, a structural editor,
or another Pages Function.

All Foundation pages use a restrained documentation composition:

- one title and short explanation;
- simple semantic sections;
- semantic tables only where the content is truly rows and columns;
- a clean grid for Icons;
- an explicit Edit action where editing exists;
- real source-derived examples.

The Core styles page must replace the current giant hand-built `div` rows with
semantic, compact presentation generated from token source. A token preview is
decorative and must not become a large empty row. Component pages use their
real Dieter HTML/CSS/spec inside a simple semantic example; DevStudio must not
add a `specimenboard` or any other parallel component-display system.
Core styles, Colors, and Typography use the final Dieter Table. Icons uses a
restrained grid. Do not generate a `Use` column or explanatory usage text:
current token source does not own that metadata, so an executor may not invent
it. The allowed table columns are token/name, source value, preview, and
explicit action where editing exists.

Table and Popup receive normal source-derived component routes at
`#/dieter/table` and `#/dieter/popup`. Together with Layouts, the corrected
expected inventory is 5 Foundation routes, 24 component routes, and 2 Policy
routes. This count is an execution target and must be reconciled against
generated source; it is not closure evidence until deployed QA passes.
