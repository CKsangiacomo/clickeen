# 127C — Page Publication and Public Serving

Status: **APPROVED FOR EXECUTION — EXECUTE AFTER 127A–127B ARE DEPLOYED AND VERIFIED**

Parent: `127__PRD__Global_Pages_Program.md`

Depends on: deployed and verified 127A and 127B

## 1. Goal

Store the Page files produced by Page Builder, publish or unpublish them, and
serve complete localized Page HTML through `clk.live` and Cloudflare.

127C also replaces the iframe and direct-`runtime.js` embed choices with one
shared `clickeen.js` installer for published Widget Instances and Pages.

127C does not generate code, translate content, compare revisions, or create a
package/version system.

## 2. Customer behavior

- Save or Update stores the exact Page source and files generated in the
  browser.
- Publish exposes the already-saved files; it does not generate or translate.
- Unpublish stops public serving and retains the Page.
- Delete removes only an unpublished Page and never deletes referenced
  Instances or assets.
- The direct `clk.live` URL opens the complete Page.
- Copy code returns the same iframe-free `clickeen.js` installer used for a
  Widget Instance.

## 3. Authorities

| Responsibility | Authority |
| --- | --- |
| Current account, member, and policy | Berlin bootstrap and Roma |
| Save, Update, Publish, Unpublish, Delete | Authenticated Roma Page routes |
| Page source, files, overlays, and publication state | Tokyo-worker account Page operations |
| Page file generation | 127B Web Code Generator in Page Builder |
| Exact locale values | Existing Page and Instance overlay authorities |
| Public response and shared installer | Tokyo-worker / `clk.live` |
| Browser-language and country hints | Request and Cloudflare metadata |
| Exact-locale cache | Cloudflare CDN |

Public requests never call Roma, Bob, Page Builder, Web Code Generator,
Translation Agent, or a child Widget URL.

## 4. Direct Page folder

```text
accounts/{accountPublicId}/pages/{pageId}/
  source.json
  serve-state.json
  overlays/
    locales/
      {locale}.json
  overlays.json
  index.html
  styles.css
  runtime.js
```

`overlays/locales/` contains authoring overlays. Root `overlays.json` is the
locale-value file generated by 127B for public response completion.

There are no Build folders, revision folders, fingerprints, candidates,
pointers, retained packages, or generated-from records.

## 5. Serving state

127C stores only the publication state needed to serve the current Page:

```ts
type PageServeState = {
  published: boolean;
};
```

127D later adds and owns the small `needsUpdate` flag and its related Publish
gate. 127C must not create, default, or require that field before 127D is
executed. No other serving fact, revision, or evidence object is stored.

## 6. Save and Update storage

Before Roma receives a Save or Update request, Page Builder has already run
127B and holds:

```text
source.json
index.html
styles.css
runtime.js
overlays.json
```

Roma:

1. resolves the current account and member;
2. applies the existing role, tier, entitlement, and Page policy;
3. validates the 127A Page source and Page/account coordinates;
4. sends the exact source and generated files to Tokyo.

Tokyo parses the submitted JSON through the replacement Page runtime owner,
validates the account/Page coordinates, and stores the submitted source and
files. This is ordinary input parsing, not a shared validator framework.

First Save creates an unpublished Page. Later Save or Update preserves the
current publication state. Save and Update are allowed while the Page is
published. A successful write purges only that Page's affected public URLs and
support-file URLs.

If the storage operation fails, Roma returns the normal Save/Update error and
does not report success. The customer can retry the ordinary action. 127C adds
no candidate package, rollback, transaction, recovery workflow, or other
replacement machinery.

## 7. Publish

Publish is a separate explicit customer action. It:

1. resolves the current account and member;
2. requires an ordinary saved Page with at least one placement;
3. applies the existing Page and tier policy;
4. requires the current Page files and saved public locale output;
5. asks Tokyo to set `published: true`; and
6. purges the Page's public URLs.

Publish never saves, generates, translates, or changes Page content.

After 127D is deployed, 127D adds its `needsUpdate: false` Publish requirement.

## 8. Public URLs

Stable Page URL:

```text
https://clk.live/{accountPublicId}/pages/{pageId}
```

Exact-locale Page URL:

```text
https://clk.live/{accountPublicId}/pages/{pageId}/{locale}
```

Direct support-file URLs:

```text
https://clk.live/{accountPublicId}/pages/{pageId}/styles.css
https://clk.live/{accountPublicId}/pages/{pageId}/runtime.js
```

Tokyo resolves the two exact support-file names before treating the final path
segment as a locale.

The exact-locale URL returns only that locale. If it is not present or is
incomplete, Tokyo returns the existing explicit public failure; it never
substitutes another locale.

The Page's saved public locale set is mechanical:

- `source.json.baseLocale`; plus
- the exact top-level locale keys in the root `overlays.json` last written by
  127B during Save or Update.

Account Settings owns which locales the existing Generate translations action
targets. Changing Settings alone does not change the saved public locale set.
Only Generate translations followed by Save or Update changes saved public
locale output.

The stable URL chooses one available exact locale in this order:

1. best supported browser-language match;
2. an available regional locale whose region subtag matches Cloudflare's
   country code;
3. Page `baseLocale`.

It then redirects to the exact-locale URL. Country is not Page identity and
does not create a locale or hidden response variant.

## 9. Exact-locale HTML response

On an exact-locale cache miss Tokyo:

1. reads `source.json`, `serve-state.json`, `index.html`, and `overlays.json`;
2. requires the Page to be published;
3. requires the requested locale to exist in the saved public locale set;
4. uses the base values already in HTML for `baseLocale`, or the exact matching
   Page and placement overlay values for another locale;
5. applies those values through 127B's field-path markers; and
6. fails the request if a required exact-locale marker value is missing rather
   than leaving the base value in place; and
7. returns complete HTML.

The response contains complete semantic content, correct `<html lang>`, Page
metadata, canonical and alternate-locale links, 127B's localized `WebPage`
JSON-LD, any supported visible-content schema, and only the requested locale
before JavaScript runs. Tokyo fills the real canonical, alternate-locale,
`WebPage.url`, and `WebPage.@id` values from the request origin,
`accountPublicId`, `pageId`, requested locale, and saved public locale set. 127B
owns the HTML and markers; Tokyo owns those public serving coordinates.

`styles.css` and `runtime.js` are the same for every locale. Public visitors do
not receive `source.json`, `serve-state.json`, or `overlays.json`.

This is stored-value response completion. It is not translation, generation,
or child Instance traversal.

## 10. Cloudflare caching

- The exact-locale URL is the HTML cache key.
- `styles.css` and `runtime.js` are cached at their direct Page URLs.
- The stable locale-selection redirect is not shared-cached because request
  language/country hints can differ.
- Raw IP/country is never part of the exact-locale cache key.

For Save or Update, Tokyo reads the previously saved public locale keys before
replacing the Page files. After the successful write it purges the union of the
previous and newly saved exact-locale URLs, plus the Page's `styles.css` and
`runtime.js` URLs. Publish, Unpublish, and Delete purge the affected Page's
saved exact-locale and support-file URLs. The stable locale-selection redirect
is `no-store` and therefore has no cache entry to purge. There is no global
purge, Page revision/fingerprint system, or request-time generator.

## 11. Shared iframe-free installation

Direct URLs remain the canonical output. No installer is required when a
Widget or Page is the top-level document.

For mounting either product inside another website, Roma returns:

```html
<script
  src="https://clk.live/clickeen.js"
  data-clickeen="https://clk.live/ACCOUNT/PUBLIC-PRODUCT"
  defer
></script>
```

For a Widget, `PUBLIC-PRODUCT` is the Instance ID. For a Page it is
`pages/{pageId}`. An exact-locale URL can be used when the host deliberately
pins a locale.

`clickeen.js` is one small, product-neutral, globally served Tokyo root asset.
For each installer element it:

1. reads the published `clk.live` URL;
2. creates one mount at that element;
3. fetches the already-completed public HTML;
4. mounts the product body in open Shadow DOM;
5. derives and attaches the product stylesheet from the same public-product
   URL;
6. loads `runtime.js` only when behavior requires it; and
7. attaches approved source-backed JSON-LD without duplicating it.

The generated HTML already contains final approved asset and content URLs.
Before mounting fetched HTML, `clickeen.js` resolves only Clickeen-generated
relative support references such as each placement's `./styles.css` against the
fetched public-product URL. It does not rewrite customer links or discover
dependencies. Tokyo serves `clickeen.js`, completed HTML, CSS, runtime
JavaScript, and required public assets with the credential-free cross-origin
headers required for the host page to fetch them. Each installer element mounts
once. A failed public fetch mounts nothing and uses the ordinary public request
error; it never falls back to partial or invented output.

It does not generate HTML, apply private overlays, translate, save, publish,
call Roma, or branch by Widget type/Page layout. There is no iframe option and
no direct artifact-`runtime.js` installer.

Clickeen Pages do not use `clickeen.js` for child Instances. 127B has already
placed their saved HTML directly into the Page.

### 11.1 `clickeen.js` source and delivery

127C adds one git-authored source file:

```text
tokyo/product/clickeen/clickeen.js
```

The existing `scripts/tokyo-r2-deploy-sync.mjs` product-root sync adds this
directory mapping, which uploads the file to the root product key:

```text
source: tokyo/product/clickeen
target: product
result: product/clickeen.js
```

The Tokyo product-root change detector in
`.github/workflows/cloud-dev-workers.yml` adds `tokyo/product/clickeen/` beside
the existing product-root source paths so a loader-only change runs the sync.

Tokyo serves R2 key `product/clickeen.js` at `/clickeen.js` before account
product routes with `application/javascript; charset=utf-8` and normal
product-root revalidation. The existing `cloud-dev workers deploy` workflow
owns deployment and verification. 127C creates no loader Worker, registry, or
separate deployment.

## 12. Unpublish and Delete

Unpublish sets `published: false`, purges the public URLs, and retains source
and files.

Delete requires the Page to be unpublished, removes the Page folder through
the normal Tokyo operation, and purges its URLs. It never deletes referenced
Instances or account assets.
